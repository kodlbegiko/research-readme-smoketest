Dear Editors,

Please consider the enclosed research note, *Why a High-Precision README Checker Failed External Validation*.

The manuscript reports a preregistered external validation of a frozen static detector for root-README install-to-first-use paths in research software. The detector achieved precision of 1.000 but recall of approximately 0.292 and accuracy of approximately 0.553, failing a preregistered 0.750 accuracy gate. Three predicted hard findings were dynamically disproved. In a separately locked ten-case dynamic validation, eight of nine testable cases completed their first meaningful task and no direct README blocker was observed. Productization was stopped, and no GitHub Action v0.2 was created or planned.

The contribution is methodological rather than promotional. The public repository preserves prediction locks, raw attempts, adjudications, permitted correction reruns, machine-readable results, checksums, an independent replication protocol, and a zero-impact baseline. The manuscript distinguishes harness errors, dependency compatibility failures, component-scope issues, and direct README defects. It also discloses that the original reference annotation was not an independent second-human process and that the dynamic cases were feasibility-selected.

We believe the note is relevant to readers interested in empirical software engineering, research software engineering, open science, documentation quality, negative results, and reproducibility. The study is offered for critical review and independent replication; confirming, contradicting, inconclusive, and blocked outcomes are all acceptable.

The manuscript is not under review elsewhere [OWNER TO CONFIRM]. No external funding is claimed. The author is the detector developer and repository owner; this conflict is disclosed. AI systems assisted with implementation, evidence organization, drafting, and editorial review, but were not treated as independent annotators, replicators, or impact evidence.
